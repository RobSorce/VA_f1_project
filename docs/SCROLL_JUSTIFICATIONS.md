# Scrollable areas: inventory and justifications

The dashboard is a fixed-viewport application: the page never scrolls, at any
window size, and no view scrolls by default. A view adapts to the box its panel
gives it (charts read their container size; tables fit or page their rows;
the Driver Comparison lays its sections and the Strategy Timeline its driver
rows in columns, then pages, that fit the pane).
The few areas that keep an internal scroll are listed below, each with the
design constraint that justifies it. Updated 2026-10-15 (V5 / V13, repairs 2 and 3;
Phase 9c: the Consistency cards no longer scroll, the Sectors panel, the race
tower of the Analyse sidebar and the dock rows below).

## The page never scrolls

- `html, body { overflow: hidden }` (`frontend/src/styles/base.css`) and the shell
  `.app-container` is exactly `100vh` with `overflow: hidden`
  (`frontend/src/styles/dashboard.css`); its body takes what the chrome rows
  (weather bar, timeline, dock) leave, with `min-height: 0`.
- An earlier rule, `@media (max-width: 1440px), (max-height: 900px)`, switched the
  app to page scroll on every window lower than 900 px. It let the Pit Wall grow
  to its lap table: a 1896 px page at 1536 x 750
  (`notes/experiments/v13_audit/findings_2026-10-14.md`). It was removed on
  2026-10-15; the chrome rows now shrink with the viewport height instead.
- Checked at 1536 x 750, 1366 x 768, 1920 x 1080 and 2048 x 1100 by
  `node notes/experiments/v13_audit/layout_fit.mjs` (output:
  `notes/experiments/phase9/layout_fit.txt`) and by
  `frontend/src/__tests__/layout.viewport.test.js`.
- Panel content never scrolls by default: `.panel-content`, `.viz-container` and
  the analytics containers are `overflow: hidden !important` (`dashboard.css`,
  "Global No-Scroll Policy").
- Zoom and pan: only the Track Map has d3.zoom (`TrackMap.jsx`). The Strategy
  Timeline and the PCA biplot have no zoom or pan; an earlier version of this
  document said they did.

## How the list is checked

`node notes/experiments/v13_audit/overflow_inventory.mjs` lists every
`overflow`, `overflow-x` or `overflow-y` set to `auto`, `scroll` or `overlay`, in
the CSS and in the inline styles of the components (React style objects, D3
`.style('overflow', …)`), and fails on any area whose key is not in the
"Inventory key" column below (output:
`notes/experiments/phase9/layout_overflow_inventory_after.txt`).
`frontend/src/__tests__/layout.scroll.test.js` runs the same check with the
test suite. Keys: `<css file> <selector>` for CSS, `<file>:<enclosing style
object or component>#<n>` for inline styles.

## Overlays, menus and popovers (opened by the user, above the dashboard)

| Area | Inventory key | Direction | Design constraint |
|------|---------------|-----------|-------------------|
| Floating overlay window | `dashboard.css .overlay-panel__content` | Both | A window the user moves and resizes (minimum 420 x 320 px, `OverlayPanel.jsx`); content larger than the size the user chose scrolls inside the window. The overlay layer keeps clear of the weather bar, the timeline and the dock (tokens `--overlay-inset-*`). |
| Settings | `dashboard.css .settings-tab` | Vertical | An accordion whose height depends on the sections the user opens; the Dock section lists every view of the dock registry, one row each. |
| Help overlay text | `dashboard.css .help-overlay__body` | Vertical | Reading text of each chart's help, of variable length, in a panel capped at `min(720px, 86vh)`. |
| Dock right-click menu | `dashboard.css .dock-ctx-menu` | Vertical | Capped at 320 px (`DockContextMenu.jsx` MENU_MAX_HEIGHT) and anchored above the clicked dock item; scrolls only when its items need more. |
| Dock overflow (⋯) popover | `dashboard.css .dock-overflow-popover__body` | Vertical | The dock items that do not fit on the dock row (`utils/dockCapacity.js`); their number depends on the user's dock and the window width. |
| Dock customise popover | `dashboard.css .dock-customize-popover__body` | Vertical | The full view registry with a toggle per view, grouped by category. |
| Dock layouts popover | `dashboard.css .layout-dock-popover` | Vertical | The layout presets and every view in a multi-column list that fits the popover; capped at `min(720 px, window height - 80 px)` (`LayoutDockPopover.jsx`), the scroll is the fallback for a registry taller than that. |
| Layout builder | `dashboard.css .layout-builder` | Vertical | Pane shapes and one view picker per slot, capped to the room under its anchor. |
| Session menu | `components.css .session-menu`, `components.css .session-menu__race-list`, `components.css .session-menu__mock-list` | Vertical | The season calendar (one row per round) and the list of cached sessions for the mock replay; their length depends on the season. |
| Command bar results | `CommandBar.css .sb-dropdown` | Vertical | Search results of variable length, capped at 400 px; keyboard-driven (the arrow keys keep the selected row in view). |
| Command palette results | `CommandPalette.css .cp-results` | Vertical | The full command list when the query is empty, capped at `calc(80vh - 56px)`; keyboard-driven. |
| Shortcut cheatsheet | `ShortcutCheatsheet.css .cs-body` | Vertical | Three balanced columns in which a section may continue in the next column (a row never splits, a title never ends a column; modal up to 92 vh, rows 2 px padding). The 42 shortcuts need at most 468 px of column at 1536 x 750 and 469 px at 1366 x 768 against 604 and 620 px of room, an upper-bound estimate (`node notes/experiments/phase9/repair_cheatsheet_fit.mjs`, output `repair_cheatsheet_fit.txt`), so no target window shows a scrollbar. The scroll is the fallback for windows narrower than 900 px (two, then one column) or lower than the target windows. |

## Areas that must not scroll

| Area | How it fits |
|------|-------------|
| Page and shell | `html`, `body`, `.app-container`, `.app-body` `overflow: hidden`; shell `100vh`. |
| Pit Wall grid | Rows `44px / 1fr / 35vh`, columns `480px / 1fr`; every cell has `overflow: hidden` and `min-height: 0`, so a cell never grows to its content (`PitWallLayout.jsx`). |
| Docked panes | Each pane is a share of its split; the tab bar shrinks its tabs (ellipsis, full name in the tooltip) and the "+" picker is a grid of every view (`DockedLayout.jsx`). |
| Dock | Never scrolls: the measured buttons that do not fit move into the ⋯ popover (`BottomTabBar.jsx`, `utils/dockCapacity.js`). The measure counts everything on the bar: the buttons, a gap between every two children, the bar's padding and border, the divider with its margins and the fixed group (Layouts, ⌘K, Settings), `dockRow`; it runs again when the web fonts finish loading, and after every render the row is checked and one more item goes to the popover while it is wider than the bar. Phase 9c: the browser pass found 1439 px of buttons in the 1400 px bar at 1536 x 750 (Pit Wall and Settings cut): the buttons were measured once, at mount, with the fallback font's labels (the default dock is 1292 px wide then, 1490 px with the Formula1 labels, `node notes/experiments/v13_audit/dock_fit.mjs`). With the real CSS and font widths the default dock keeps 8 of its 10 items (+ ⋯) at 1536 x 750, 9 at 1366 x 768, all 10 at 1920 x 1080 and 2048 x 1100 (`frontend/src/__tests__/dock.fit.test.jsx`). |
| Weather bar | One row; up to 1440 px wide the event name says "GP" for "Grand Prix" ("Italian GP", 66 px in its 109 px box at 1366 x 768; "Italian Grand Prix", 118 px, was cut by 15-22 px), a name still too long ends in an ellipsis with the full name in its title; weather pills that do not fit are hidden whole, never cut. |
| Timeline legend | One row that wraps on a narrow window (`.timeline-player__legend`). |
| Leaderboard rows (Analyse sidebar) | Every row is a share of the tower body (`calc(100% / n)`) moved by `translateY(k x 100 %)` of its own height (`Leaderboard.jsx`, `utils/views/leaderboard.js` towerRowStyle / towerBodyStyle); the body takes the room the sidebar's flex column leaves it, at most 28 px a row, so the rows fit without a measure and a resize starts no transition. The measure only decides to page (`chartBox.js` fitRows, 18 px floor; pageOf, a ▲ ▼ pager line). Below 900 px of window height the legend opens from a "?" key as a card over the rows; the focus driver's cards (`SidebarFocusCards.jsx`) stay collapsed to their header lines under 1200 px, "Details" laying them over the sidebar. At the four target viewports the 20 rows show on one page in every state: 24 / 21 / 18 px at 1536 x 750 (no focus driver / focus driver / focus driver with a flag banner and the forecast footer), 25 / 22 / 19 px at 1366 x 768, 28 px at 1920 x 1080 and 2048 x 1100 (`node notes/experiments/v13_audit/panel_fit.mjs`, `frontend/src/__tests__/leaderboard.fit.test.jsx`). Phase 9c: the browser pass found a 440 px body with 554 px of rows (P16-P20 below it): the rows' translateY was in px, 19 x 28 + 22 = 554 being the first render's 28 px spacing that the row transition had not left; before that, an inline height of 20 rows in an overflow-hidden wrapper cut the rows under the focus cards. |
| Sectors panel (Live, Best, Top Speeds) | No scroll and no cut row (`SectorsPanel.jsx`, `utils/views/sectorsPanel.js` sectorsRowFit / sectorsColumnsFit): the rows take the measured body, 26 px down to 18 px, else they are paged (the same page of ranks in every column, a ▲ ▼ pager line under them); the ranked columns (Best: 3 sectors, drawn by `SectorsBestTab.jsx`; Top Speeds: 4 traps, the unit in each column's header) are at least 16 data-type ems wide (a ranked row at the real font widths) and paged with ◀ ▶ when the width holds fewer. In the preset panes: Pace 609 x 286 at 1536 x 750: Live 9 rows a page, Best 3 columns x 10, Top Speeds 3 of 4 columns x 8; Overview 609 x 257: 7 / 9 / 7 rows a page; 1366 x 768 (541 px wide): 2 of 3 and 2 of 4 columns; Pace at 1920 x 1080 (794 x 452): Live and Best 20 rows at 18 px, Top Speeds 3 of 4 columns x 18; Pace at 2048 x 1100 (858 x 463): all 20 rows of every tab (Live and Best at 19 px, Top Speeds 4 columns at 18 px) (`node notes/experiments/v13_audit/panel_fit.mjs`, `frontend/src/__tests__/sectors.fit.test.jsx`). The fit measures the first column's body; the columns of a page share one header row (`dashboard.css` `@supports (grid-template-rows: subgrid)`), so every body is that tall, and the column titles are in the Bold face, so a title and its "Lap N" stay on one line in a 16 em column. The verifier of round 1 found each header wrapping on its own: "FINISH LINE" and "SPEED TRAP" on three lines next to a two-line "SECTOR 1" left those bodies about 17 px shorter than the one measured, P20 cut by about 7 px at 2048 x 1100. Whether the pager line was on screen travels with each measure of the body (`chartBox.js` useBoxSize tagRef), so a render before the measure that sees the pager never unpages. Before Phase 9c the 20 rows were drawn into overflow-hidden bodies and cut, with no scroll and no pager (browser pass 2026-10-16). |
| Consistency cards | No scroll in a preset pane (`ConsistencyPanel.jsx`, `utils/views/consistencyLayout.js`): a collapsed card is one line, 30 px down to 20 px; the cards are laid in as many columns of at least 32 data-type ems as the width holds; an expanded card (the focus driver's, a chevron, "Expand all") spans its row with its measured height; the cards that do not fit go to pages, with a ◀ ▶ pager in the panel's header line; the page shown is the one that holds the card the user acted on last (expanded or collapsed, or the first card of a page reached with the pager), else the focus driver's, so a card just expanded stays on screen when the pages move. Pace preset at 1536 x 750 (1225 x 228): the 20 cards on one page in 3 columns at 22 px (4 columns at 30 px at 2048 x 1100); Overview (609 x 257): 1 column, 3 pages of 7, 7 and 6 cards; with the focus driver's card expanded (155 px, three compounds) it shares a page with one line. "Expand all" pages the expanded cards one or two at a time (`node notes/experiments/v13_audit/panel_fit.mjs`, `frontend/src/__tests__/consistency.fit.test.jsx`). An expanded card is never taller than the area: only in a floating overlay near its minimum size, where it would be, its details scroll (row "Consistency expanded card" above). Before Phase 9c the grid scrolled: 2-6 of the 20 cards were visible at 1536 x 750 even with every card collapsed. |
| Timing Tower columns (Pit Wall) | The column widths are shares of the 480 px timing column (476 px of design widths drawn as percentages, `table-layout: fixed`, `TimingTower.jsx` COL). The tower's text stays at the 11 px data floor at every viewport (`--font-size-data-fixed`, CHART_FONT.fixed), because its columns do not grow with the window; every cell and header fits its column at that size (`notes/experiments/phase9/repair_tower_columns.txt`), so no value ends in an ellipsis; there is no horizontal scroll. |
| Pit Wall side column (Weather, Race Control, Ask box) | Weather and the Ask box keep their height and Race Control takes the rest, newest message first (`PitWallLayout.jsx`): at 1536 x 750 the 263 px column leaves Race Control 102 px, three message lines (`layout_fit.txt`); the quick answer is a card laid over the column (row above). |
| Driver Comparison | The six sections (gap and lap charts, sectors, top speeds, race summary, tyres) are laid in columns of at least 320 px and in pages that fit the pane (`utils/views/driverCompare.js` comparePages, ◀ ▶ pager): in the overview preset 2 pages at 1536 x 750 and 1366 x 768, 1 page at 1920 x 1080 and 2048 x 1100 (`notes/experiments/phase9/repair_compare_fit.txt`). |
| Strategy Timeline | Driver rows at least ceil(data type + 9) px high; a wide, low pane lays them in up to 3 columns, a narrow one pages them (fitRows / pageOf, pager in the panel header). Pit Window preset: all 20 drivers in 3 columns of 7 rows at 1536 x 750 and 1366 x 768 (`notes/experiments/phase9/repair_strategy_fit.txt`). |
| Race Pace Grid (Pit Wall centre, dock) | The cells take the panel width (`utils/views/racePaceGrid.js` paceColumns: 78 px down to 36 px, the label shortened to what the cell holds, the glyph always kept, the full time in the tooltip; below 36 px the driver columns are paged) and the rows its height (fitRows, 26 px down to 18 px); the laps that do not fit are paged: the most recent ones follow the replay, older ones a page back with ◀ (paceLapWindow). At the four target viewports the 20 driver columns fit the Pit Wall centre in 42 to 76 px cells (`notes/experiments/phase9/integrate_grid_fit.txt`). The lap pager's slot is always in the legend bar, hidden while every lap fits: the browser pass (2026-10-16, 1536 x 750) found 12 rows (246 px) fitted to the grid measured before the pager, which then wrapped the bar onto a third line and left the grid 237 px (9 px cut); with the slot reserved the bar is the same paged or not, and the rows are fitted to the final grid (`frontend/src/__tests__/pacegrid.pager.test.jsx`). |
| Strategy views (Race Prediction, Strategy Simulator, Race Analysis, Cross-Race Analysis, Undercut Calculator, Sector Delta, Race Control, Strategy Engineer) | Charts read their box (`utils/views/chartBox.js` useBoxSize) and draw what fits (Sector Delta: the most recent laps its width holds; Undercut: every candidate lap as a column); tables and lists fit their rows to the height and page the rest with ◀ ▶ (`chartBox.js` fitRows / pageOf); the Simulator splits Plan / Result / Compare into tabs; the Strategy Engineer's analysis box is capped at 40 % of its tab (`visualizations.css .strategy-console__response`), the whole answer being in the chat log. No scroll area is left in these files (`notes/experiments/phase9/d3ports/overflow_inventory_after.txt`). |
| Track Map | d3.zoom inside a fixed viewport; no CSS scroll. |
